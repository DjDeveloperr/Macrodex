# Agent Memory

- Food search suggestions must come from one shared ranked/deduped path across dashboard, home, and conversation composers. Do not add another local matcher unless it feeds that shared path.
- Food suggestions must be meal-context aware. Foods the user usually logs for the current meal should outrank generic recent or wrong-meal items, and the focused fixture should prove meal-specific frequent foods win.
- Frequent foods should not be evicted by recency-only sorting. Keep enough food memory loaded and rank frequent staples ahead of one-off recent foods where appropriate.
- Composer controls should bottom-align as the text input grows; plus, search, voice, stop, and send buttons should not float vertically centered beside multiline text.
- Dashboard keyboard lift must be computed from the unshifted composer frame so an existing offset is not applied twice after search sheets, food selections, or keyboard frame changes.
- UI polish changes need simulator or device visual checks when feasible, especially composer, keyboard, drawer gestures, search popups, widgets, and Liquid Glass surfaces.
- Widgets must be rendered and visually inspected from actual WidgetKit SwiftUI output before claiming polish. Keep rendered screenshots/previews for affected widget families and verify they do not clip, truncate, or depend on invisible widget-only backgrounds.
- iOS AI/Siri integration should expose typed App Intents, AppEntities, and App Shortcuts that return structured data; Siri/Apple Intelligence should compose answers from those entities instead of the app baking Siri prose into UI-only flows.
- Food Spotlight indexing must include favorites, most logged foods, and recent foods; each result should deep link to food details and expose a log-today quick action when the public APIs support it.
- FoundationModels support must use only public SDK symbols. Keep `system` as the no-login default; wire `pcc` through iOS 27's `PrivateCloudComputeLanguageModel` only behind Xcode/iOS 27 SDK gates, with `com.apple.developer.private-cloud-compute` in app entitlements. Verify stable Xcode still builds and Xcode beta compiles the PCC path; runtime PCC may require a physical iOS 27 device while simulator beta bugs remain.
- TestFlight build numbers must use Macrodex's timestamp format `YYYYMMDDHHMM`, not `GITHUB_RUN_NUMBER`; small numeric builds like `68` get buried behind existing timestamp builds. Verify with the CI `Set TestFlight build number` log and ASC/TestFlight showing the timestamp build at the top of the Public Beta group.
- TestFlight duplicate-build reports usually mean more than one main push workflow reached upload. Keep the iOS workflow concurrency group on workflow plus ref, cancel in-progress main push runs, and verify with `gh run list`/ASC that only the intended latest run uploads after a push.
- TestFlight HealthKit/App Group claims must be checked against the signed IPA entitlements, not just source `.entitlements` files or embedded provisioning profiles. Verify `codesign -d --entitlements :-` on the exported/uploaded IPA includes `com.apple.developer.healthkit` and `group.com.dj.macrodex`, then confirm on a physical device that HealthKit no longer reports a missing entitlement.
- AdHoc Store uploads for iOS 27 should use the local Xcode beta SDK, timestamp `CURRENT_PROJECT_VERSION`, `adhocstore upload --sign --require-reprovision`, and signed-entitlement verification. Do not accept wildcard-profile fallback when App Groups, HealthKit, or future PCC entitlements matter.
- Backup/restore UI must be truthful after app deletion/reinstall: local SQLite backups inside the app sandbox do not survive uninstall, and iCloud must only be shown as working when the app can resolve its ubiquity container. Verify by deleting/reinstalling or using a fresh container, confirming cloud backup discovery/import works when available, and clearly showing unavailable cloud state otherwise.
- Dashboard pull-to-compose must behave like pull-to-refresh: gate any drag fallback with real scroll distance from top plus a top sentinel, so normal scrolling or a return-to-top swipe cannot open the composer. Keyboard lift must not stack with the pull reveal. Verify with a real scroll interaction plus keyboard-open screenshot/video.
- HealthKit nutrition recovery must request exact nutrition read permission and hydrate the full weekly-strip history range, not only the selected week. If HealthKit returns no data, surface the permission/query reason instead of silently showing local-only zeros.
- Interactive keyboard dismissal must derive composer padding from continuous keyboard overlap, not a visible/hidden flag. Keep one bottom-backdrop owner, extend it beneath container and keyboard safe areas, and verify partial dismissal plus rounded keyboard corners on simulator/device.
- Drawer header blur must be driven by actual scroll-under distance, remain absent at rest, and be inspected both mid-drawer gesture and after scrolling in dark mode; content must not remain legible through or collide with the fixed title.
- AI nutrition estimates are drafts, never silent logs. Debounce requests, preserve explicit portions/calories, show reviewable values, translate model failures into retry/manual recovery, and visually verify both success and unavailable-model states.
